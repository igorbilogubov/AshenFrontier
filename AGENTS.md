# Работа над Ashen Frontier

## Аккаунты — новая локальная реализация 16 сентября

Текущий код требует Google-входа и использует PostgreSQL schema 6 (аккаунты введены миграцией 5, сборки/таланты — миграцией 6): до пяти героев на аккаунт, protocol 3 `join {heroId}`, ровно одно игровое соединение аккаунта. Секреты героя/localStorage-авторизацию не возвращать. Google `sub` определяет аккаунт; cookie HttpOnly. Истечение сессии/выход останавливают онлайн-AFK. Перед настоящим входом нужны GAME_PUBLIC_ORIGIN, GOOGLE_CLIENT_ID и GOOGLE_CLIENT_SECRET; см. [docs/ACCOUNTS.md](docs/ACCOUNTS.md) и [docs/GOOGLE_AUTH_SETUP.md](docs/GOOGLE_AUTH_SETUP.md).

Общий 4732 и production остаются на schema 4 и ещё не переключены на аккаунты/навыки/новые регионы; не выдавать проверку тестовой cookie за реальный Google-вход. Прежние герои мигрируют без владельца и не присваиваются первому аккаунту; решение о необходимости их административной привязки ожидает ответа пользователя. Существующие строки не удалять. Тесты авторизации используют только временную PostgreSQL и fixture-сессии, открытого тестового входа в обычном сервере нет.

## Согласованные ограничения

- Выбраны Three.js + TypeScript и браузер как основная версия; desktop планируется на том же веб-клиенте. Основной клиент, сервер и общие правила переведены на строгий TypeScript. Следуй [TECHNICAL_DIRECTION.md](TECHNICAL_DIRECTION.md). Проба Godot удалена из рабочей папки по запросу пользователя; не возвращай её код, сборки и инструменты без нового запроса. iOS/Android-сборки не запускать без нового запроса.
- Камера с фиксированным ракурсом; вращение разрешено в мастерских моделей, в игре только зум и следование за героем.
- Движение только при удержании ЛКМ в сторону текущего курсора; отпускание прекращает движение. ЛКМ по противнику не атакует; по личной добыче/торговцу запускает отдельный серверный подход. Пробел и удержание ПКМ повторяют обычный удар. Не возвращать движение с WASD/стрелок, маршрут по клику/миникарте и пассивный поворот за мышью без нового запроса. Клавиши 1/2/3/4 для четырёх навыков, Q/W для назначенных зелий и Shift для шага/бега остаются. Любой вид зелья можно назначить на Q или W из рюкзака; назначения опубликованы в `20260916-consumables-afk-01`. ЛКМ по порталу/торговцу/личной добыче запускает серверное взаимодействие.
- Три класса: воин, лучник, маг. Класс выбирается только при создании героя и больше не меняется; существующие герои сохраняют текущий класс. Ровно шесть слотов снаряжения: оружие, доспех, шлем, сапоги, кольцо, амулет.
- Локальный мир 16 сентября: лес (72 моба), Стадиум (24), Снежный предел (98) и Пепельные пустоши (98), всего 292 спавна. Снег 180 × 165 м доступен с 10 уровня через восток леса; пустоши 160 × 160 м — с 25 уровня через снег. Общая геометрия/спавны — `snow.ts` и `wasteland.ts`, вид — соответствующие `*-environment.ts`. Пустоши добавляют четыре собственных GLB: `ash-jackal`, `scorpion`, `monitor-lizard`, `scarab`. Именные элиты передают `eliteId`; для HP/дропа/масштаба использовать `mobConfig`. Синий дроп только у именных элит: 3% абсолютного шанса. [Снег](docs/SNOW_WORLD.md), [пустоши](docs/WASTELANDS.md).
- Навыки и таланты согласованы и реализованы локально: по 12 навыков на класс, четыре назначаемых слота 1–4, книга K, три пресета. Открытия 1/3/5/8/10/14/18/22/27/32/38/45; по три ветки класса, пять малых талантов × два ранга и один итоговый, всего 54 определения. Очко с 10 уровня и каждые четыре далее, максимум 20 к 86; только один итоговый талант при восьми очках в его ветке. Смена в безопасной зоне отменяет собственные бафы/подготовленные действия и AFK, сохраняет откаты; открытие книги не мешает бою и не меняет HUD. AFK использует только установленные неподвижные навыки. `skillBuild`, `buildRevision`, `skillPresets` сохраняются в migration 6. [Контракт](docs/SKILL_BUILDS_SERVER.md), [аудит баланса](docs/SKILL_BALANCE_ALPHA.md). Старое предложение не является актуальным ограничением реализации.
- Основа воина — Mixamo Exo Gray, тяжёлый комплект Paladin сохраняется. Округлый манекен и гладкая процедурная кожа отвергнуты пользователем; актуальные источники — art/characters/mixamo-classes-v1/.
- Рюкзак содержит 16 общих ячеек для ненадетых вещей и непустых стопок зелий отдельно от шести слотов героя. `items` хранит все экземпляры, `equipment` — ссылки; для вместимости использовать `backpackUsage`, не длину `items` или только `backpackItems`. `stash` ссылается на 32 личные вещи в сундуке; они также исключаются из рюкзака, зелья в сундук не переносятся. Schema 4 сохраняет старые бутылки; временное `consumableOverflow` допускает только прежнее заполнение сверх 16 и уменьшается при освобождении места. Открытие инвентаря/статов не блокирует бой, не отключает AFK и не меняет HUD. Иконки конкретных вещей — `public/game/item-icons/`, контурные подсказки только для пустых слотов/статов.
- Нижний HUD: круглая красная колба HP слева от семи равных центральных действий (атака, четыре навыка, HP/MP), синяя колба маны справа; C/I справа внизу. Уровень жидкости и текущий/максимальный запас отражают серверное состояние.
- В MVP экипировка даёт обычные характеристики, включая скорость атаки/каста; модификации отдельных навыков и особые боевые срабатывания на вещах отложены по запросу пользователя. Целевой режим — 2–3 активных часа в день плюс AFK, примерно три месяца развития. Предел100, семь полевых карт и подземелья реализованы локально по последующему согласованию; подробности в STATUS и docs/DUNGEONS.md. Около90дней остаётся расчётной целью из MVP_90_DAYS.md. Заточка пока только визуальный предпросмотр новых комплектов, правила кузнеца не выбраны.
- Новые найденные вещи имеют случайные значения в диапазонах, выбранные один раз сервером при появлении на земле и сохранённые после подбора. Не перебрасывать статы при надевании/входе; не менять диапазоны сохранённой версии без миграции. Помимо десяти начальных основ на класс, добавлены по два полных шестислотовых комплекта на 10/25 уровни: 36 новых основ и 36 редких версий, всего 132 определения (66 зелёных / 66 синих). Дроп выбирается через `regionalEquipment` по классу, редкости и региону смерти моба; Стадиум использует лесной пул. Старые диапазоны не меняются. [Региональные вещи](docs/REGIONAL_EQUIPMENT.md). Примерка доступна для всех классов/регионов; образцы мастерской не выдаются игровому герою. Торговец продаёт по шесть базовых вещей каждого класса с минимальными значениями диапазонов; продажа доступна только у него при открытом магазине. Привязанные вещи также можно продать после снятия; предметы в сундуке сначала забираются в рюкзак.
- Золото каждого подходящего kill лежит личной стопкой, вещь — с шансом 10% у обычного моба и 40% у вожака, не более одной вещи на получателя. Тестовый AFK подбирает личную добычу по сохраняемым фильтрам золота/редкости только в пределах обычной дистанции подбора, без перемещения; ручной подбор останавливает AFK. Пустые волны и полная сумка не выключают AFK. Объекты живут 180 секунд, ограничены 48 на героя и пропадают при рестарте. [Правила](docs/LOOT_VENDOR.md).
- Платежи отложены до выбора пользователем провайдера. Онлайн-автоохота включается в любой допустимой точке при открытом соединении и стоит на месте; в безопасной зоне ждёт без атак. Споты и загоны задают плотность мобов, а не право включения AFK; офлайн-AFK, PvP/PK и рынок остаются планом.
- Сервер определяет движение, бой и награды. Общие величины карты, дальности и тайминги согласовывать с клиентом; не переносить доверие к деньгам/урону на клиент.
- Новая PostgreSQL начинается с чистых героев без импорта старого JSON по явному решению пользователя. На текущем тестовом этапе по уточнению пользователя от 16 сентября не делать новые резервные копии базы героев и не проводить отдельную сверку сохранности героев до новой инструкции или изменения контекста. Существующий PostgreSQL volume использовать как есть: не удалять и не заменять его, не отключать настроенное расписание копий и не удалять прежние архивы. Изолированные тесты по-прежнему используют временную PostgreSQL. Остальные сайты на Hetzner сохранять.

## Код, ассеты и данные

Игровой код — строгий TypeScript, ES modules; сборка `npm run build` в `dist/`. Скрипты и тесты остаются JavaScript. Node.js 24, `ws`, `pg`, Three.js; тесты — `node:test` и временная настоящая PostgreSQL. `npm ci` восстанавливает зависимости из lock-файла. Поставляемый клиент использует `public/game/vendor/`, поэтому изменение версии npm-пакета Three.js само по себе не обновляет браузерную библиотеку.

`data/` (включая PostgreSQL-кластер/закрытую строку подключения), `artifacts/`, `backups/`, резервные копии, `.env*`, ключи и содержимое `heroes*.json` не коммитить и не выводить. Даже приватный репозиторий не является хранилищем секретов. Тесты используют временные БД/героев; онлайн-проверка создаёт реальные записи и выполняется только когда это входит в задачу.

Основные модели, GLB, исходные FBX, Blender-сцены, генераторы и отчёты сборки входят в репозиторий. Логи и автоматические `.blend1`-копии исключены. Перед генерацией читай README ассета: генератор перезаписывает `.blend`, `.glb`, рендер и отчёт. Проверяй именно экспортированный GLB в браузере. `art/creatures/wolf-v1-reference/` — неизменяемая контрольная версия для сравнения. Правила происхождения ассетов — [ASSETS.md](ASSETS.md).

## Проверки и передача результата

Фиксируй завершённые логические изменения отдельными локальными коммитами. Push выполняется только после отдельной команды пользователя; подготовка коммита или проверка не разрешает публикацию. Это правило действует и для работы в нескольких чатах. Пока push не разрешён, оставляй готовые коммиты в ветке и сообщай её имя.

Запускай `npm run check` и `npm test` после изменений кода. Для FPS используй изолированный `npm run stress`, методику и ограничения из [PERFORMANCE.md](PERFORMANCE.md); обычные сохранения и production для нагрузки не использовать. Для изменений вида/анимаций нужна также проверка в браузере; для серверных изменений — соответствующие проверки сети, миграций и сохранений. Успешные тесты не означают успешную выкладку.

В описании PR укажи результат, затронутые общие файлы/контракты, проверки и ограничения. В общей папке коммить только файлы своей задачи; общий контракт изменяется последовательно. PR подготавливается, когда это входит в запрос. Не выполняй force push в `main`. Бинарные модели не объединяются текстовым merge: согласуй одну версию исходника и пересобери экспорт.

В том же логическом изменении обновляй затронутые документы: STATUS/GAME для поведения, QA для доказательств, дизайн для принятого продуктового решения, ASSETS/README модели для графики. Поддерживай различие между готовым кодом, планом и опубликованным релизом. Исторические записи с датами не переписывай как новые результаты.

## Production

Приватный GitHub: https://github.com/igorbilogubov/AshenFrontier . Push и merge не запускают deployment. Обновляй production, когда это входит в запрос пользователя; уже данное разрешение повторно не запрашивай. Порядок и точный сервер указаны в [DEPLOYMENT.md](DEPLOYMENT.md). PostgreSQL-compose развёрнут в опубликованном релизе; локальные последующие миграции не считаются выкладкой. Используй отдельный релиз и проверку после переключения. Пока действует уточнение пользователя от 16 сентября для текущего тестового этапа, пропускай создание новой резервной копии базы героев и отдельную сверку строк героев, сохраняя существующий volume и не меняя уже настроенные копии/архивы; это не разрешение удалять или заменять данные и не постоянное правило для будущего production. Старый серверный JSON не импортируется в новую БД и остаётся архивом по решению пользователя; локальные данные не заменяют серверные. Caddy и чужие контейнеры сохранять.

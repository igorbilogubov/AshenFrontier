## Подготовка PostgreSQL — локальный код, ещё не deployment

Начиная с текущего `main`, `server.ts` требует PostgreSQL и не читает прежний JSON. `deploy/compose.yaml` добавляет закрытый сервис `postgres:18.6-alpine`, постоянный именованный volume и отдельного пользователя игры. Эта конфигурация подготовлена, но Docker-сборка/переход на Hetzner в текущей задаче не выполнялись. Ниже описана историческая инфраструктура последнего проверенного JSON-релиза, а не процедура запуска нового HEAD без дополнительных действий.

Перед разрешённой выкладкой нового кода подготовить два случайных hex-пароля `ASHEN_DB_PASSWORD` и `ASHEN_PG_ADMIN_PASSWORD` в серверном env-файле с правами 0600, не в Git. Проверить отдельный релиз/образ и миграции на временной БД, затем поднять БД с неизменным Compose project name `ashen-frontier` и её volume. После переключения `/health` должен подтверждать `storage.backend=postgresql`, `writer=true`, `pending=false`. Сохранить Caddy, proxy-сеть и чужие контейнеры.

Для этого перехода пользователь разрешил не импортировать прежних JSON-героев: архивировать серверный JSON отдельно, не заменять его локальным. Для уже появившихся PostgreSQL-героев будущие обновления сохраняют данные. Текущий JSON-cron не защищает PostgreSQL: нужен отдельный `pg_dump` и проверка `pg_restore` до объявления нового production-релиза. Совместимость отката проверять с конкретной схемой; старый JSON-образ не умеет читать новые PostgreSQL-сохранения. [Контракт, локальные команды и проверенный backup/restore](docs/DATABASE.md).

## Следующее обновление

Для параллельных задач сначала завершить и проверить согласованные изменения в общей папке на `main` по [WORKFLOW.md](WORKFLOW.md). Выкладывать чистый согласованный commit; записать его SHA рядом с идентификатором нового релиза и результатами проверки. Git push/merge сами по себе сервер не изменяют. Рабочий сервер не использовать как общую тестовую среду незавершённых веток.

Создать отдельный каталог `/opt/ashen-frontier/releases/<release>` и уникальный тег образа. После перехода на TypeScript передать `server.ts`, `world.ts`, загрузчик `server.mjs`, `shared/`, `stress/`, `public/`, `tsconfig.json`, `scripts/build.mjs`, package-файлы, Dockerfile и deploy-конфигурацию. Docker собирает `dist/` на отдельном этапе, в runtime устанавливаются только production-зависимости. `GAME_STRESS` в production запрещён; диагностические API не активируются. Не передавать локальные данные, node_modules, .env, артефакты или Blender-исходники. Собрать и проверить образ, пока прежняя игра работает. Затем штатно остановить только игру, сделать закрытую резервную копию актуальных данных и запустить новый образ:

```sh
ASHEN_RELEASE=<release> docker compose -f deploy/compose.yaml up -d --no-build --wait game
```

Проверить публичные HTTP/WSS, сохранения и другие сайты; только после успеха обновить ссылку current. Сохранить предыдущий образ/релиз и копию данных.

## Откат с 3D на прежний пиксельный сервер

Версии данных несовместимы по координатам и новым полям. Старый образ: `ashen-frontier:20260911-03`, каталог `/opt/ashen-frontier/releases/20260911-03`.

1. Штатно остановить только `ashen-frontier` и отдельно сохранить текущие версии 2; не уничтожать накопленный после перехода прогресс.
2. Для возврата именно к старому миру восстановить защищённую копию `heroes-before-20260914-3d-01.json` в каталог данных, сохранить владельца 1000:1000 и права 0600. Это откатывает изменения после перехода; выполнять только при принятом решении об откате данных.
3. Запустить предыдущий Compose с `ASHEN_RELEASE=20260911-03`, проверить его health/сохранения и вернуть current на предыдущий релиз.

Для обычного отката между совместимыми 3D-релизами сначала проверить совместимость схемы и по возможности сохранить новые данные. Не выполнять `docker compose down` в `/opt/n8n`, не заменять Caddyfile конфигурацией только игры и не перезапускать чужие контейнеры.

### Откат этого релиза

Предыдущие образ и каталог `20260914-3d-03` сохранены, но V2-сервер не поддерживает распределённые статы и ману V3. Не считать откат образа автоматически совместимым с новыми сохранениями и не восстанавливать старый JSON поверх накопленного прогресса. Сначала штатно остановить игру и сохранить текущий V3 в отдельную защищённую копию. Предпочтителен исправленный V3-релиз; возврат к V2 требует явного решения о данных и проверки конвертации. Копия перед релизом служит точкой восстановления, её применение откатит прогресс после переключения. Остальные контейнеры и Caddy при откате не трогать.

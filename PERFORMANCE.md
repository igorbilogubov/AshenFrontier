# Производительность: первый воспроизводимый профиль

15 сентября 2026. Строгий TypeScript перенесён и проверен; изменение языка само по себе не ускоряет игру. Профиль проведён на локальной ветке `codex/character-stats`, после миграции `33cac6e`. Production и Godot не участвовали.

## Вывод

Обычная сцена сейчас даёт около 29 FPS; полный лимит 16 сессий и бой — около 26–29 FPS. Стабильные 60 FPS ещё не достигнуты. Контрольный rAF с действующей сетью, но без работы игрового кадра даёт 59.8 FPS. Основная область для оптимизации — клиентский вывод сцены и анимированных моделей; локальный сервер укладывается в интервал 50 мс. Этот результат не обосновывает переход на Rust/Wasm.

Выявлена и устранена лишняя работа в клонах героя: `SkeletonUtils.clone` создавал 14 Skeleton для 14 skinned primitives с одинаковыми костями. Теперь части **одного** героя делят один скелет, разные герои сохраняют независимые кости и GPU-текстуры. Сравниваются также inverse bind matrices, bind matrices самих мешей остаются прежними. Уходящий герой освобождает GPU-текстуру скелета.

В сопоставимых прогонах 16 героев число зарегистрированных Three.js GPU-текстур снизилось с 164 до 64. Среднее время кода кадра уменьшилось примерно с 17.0–17.6 до 15.0–15.3 мс. Устойчивого прироста FPS в лагере это не дало: до 28.1–28.2, после 26.2–27.0. Уменьшение ресурсов подтверждено; обещать ускорение FPS по этому измерению нельзя. Геометрия и деформированные вершины всех семи клипов проверены тестами, внешний вид сохранён.

## Условия

- Apple M1, 8 CPU-ядер, 16 GiB RAM, питание от сети; macOS Darwin 25.6.0.
- Chrome 152, аппаратный WebGL2 через ANGLE/Metal. Окно игры 1527×810 CSS px, фактический DPR 1.10, обычные тени PCF 2048², стандартный фиксированный ракурс/зум.
- Один видимый браузерный клиент; остальные сессии — настоящие WebSocket-боты в том же локальном процессе Node 24.19.0. Это проверяет общую сцену и текущий протокол, а не 16 полноценных браузеров.
- Отдельный временный каталог и новые тестовые герои; уровни, урон и смерть настоящие. Положение/прогресс тестовых героев сбрасываются перед сценарием. Число мобов — 7; в бою живые/мёртвые и снаряды меняются, их число записано в отчёте.
- После появления всех моделей — 5 секунд прогрева, затем 12 секунд измерения. Первая серия — 10 основных + 3 контрольных прогона; повторная — 13. В каждой серии лагерь на 16 игроков повторён с исходной графикой.
- Godot-процессы остановлены. Другие приложения пользователя оставлены открытыми. На компьютере есть фоновая нагрузка и swap; это замер рабочего Mac, не чистая аппаратная лаборатория. В первом прогоне на 4 игроках было 19.4 FPS против 28.8 после: этот выброс нельзя честно приписать только исправлению скелетов.

## Что подтверждено и что остаётся гипотезой

**Клиентский рендер — существенная часть затрат.** В лагере 16 героев передаётся около 1.54 млн треугольников и 405 вызовов рисования за кадр, включая проход теней. Без вывода 3D, но с анимациями/DOM, получается 42.4 FPS; с одним rAF и сетью — 59.8. GPU-query доступен и не показал disjoint; обычная сцена на 16 героях — примерно 48–52 мс/query, DPR 0.75 и скрытые деревья — около 40–41. Эти времена нельзя складывать с CPU как независимые последовательные этапы или интерпретировать как процент загрузки GPU.

**Лес и разрешение влияют, но не объясняют всё.** 109 деревьев сейчас входят в крупные InstancedMesh: их листва содержит около 293 тыс. треугольников до теней, без отсечения отдельных деревьев. Диагностическое скрытие деревьев и уменьшение DPR дали около 30–31 FPS. Это не готовые настройки качества и не предложенный новый внешний вид.

**Отключение одних теней, подписей или сэмплирования клипов не дало стабильного выхода на 60 FPS.** Анимация — часть расходов, но переписывать её на Rust первым действием этот результат не оправдывает. Полный CPU/GPU-профиль драйвера и браузерного layout здесь не снят: запись разбита на участки игрового кода, GPU query и контрольные сценарии, а не DevTools trace.

**Выбор моба не доказан главным виновником.** Первый бой с проверкой raycast каждый кадр дал 18.9 FPS, повторный — 29.0. Состав живых мобов/боевые события не идентичны. Нельзя объявить raycast причиной этого разброса без отдельного фиксированного сценария с живыми целями.

**Локальный сервер не исчерпал 50 мс бюджета.** При 16 сессиях p95 полного тика обычно 6–8 мс, включая симуляцию и подготовку/отправку снимков. Сетевой генератор находится на том же M1, условия VPS с 0.5 CPU/256 MiB не воспроизведены. Это не доказательство длительной вместимости production.

Следующие ограниченные задачи: разделить лес на отсекаемые участки; ввести корректные общие границы видимости персонажей/мобов без обрезания анимаций; проверить детализацию и тени на дистанции. Каждый шаг сравнивать с исходной графикой при том же окне и числе акторов. Затем повторить на Windows с интегрированной графикой и провести длительный тест памяти/соединений. Массовое PvP/AFK, мобильный GPU, загрузка холодных ассетов и часы работы пока не измерены.

## Повторный запуск

```sh
npm ci
npm run check
npm test
npm run stress
# В браузере: http://127.0.0.1:4742/?stress=1&session=benchmark
# После завершения:
npm run stress:report
```

Нажать «Запустить весь тест» либо выбрать сценарий и «Проверить выбранный». Вкладку держать активной, не менять размер окна, зум и управление. Скрытие, потеря фокуса, ручное управление, смена числа игроков или потеря связи делают прогон недействительным. «Остановить» завершает текущий замер без записи действительного результата. После серии боты отключаются и тестовый наблюдатель возвращается в лагерь. Для окончания работы сервера — Ctrl+C. Новый запуск всегда создаёт другой временный мир; прежние игровые сохранения не используются.

`STRESS_PORT=4743 npm run stress` выбирает другой свободный порт. `/__stress/*` доступен только в явно включённом локальном стенде, проверяет loopback/Origin. Запуск режима на production, публичном host или с обычным каталогом героев отклоняется до чтения/изменения сохранений. На обычном сервере диагностические маршруты закрыты.

Исходные JSON с каждым необрезанным интервалом кадра, распределениями CPU/GPU, количеством сущностей/ресурсов, задержкой последнего снимка и серверными измерениями находятся в игнорируемом `artifacts/performance/`. `npm run stress:report` формирует сводный Markdown. В репозитории сохранён компактный числовой снимок всех 26 прогонов: [performance-2026-09-15.json](docs/performance-2026-09-15.json). Тестовые ключи/сохранения в отчёты не входят.

# Пепельный рубеж

Браузерная онлайн-RPG: общий 3D-мир «Пепельная опушка», фиксированная изометрическая камера, персонаж и животные из Blender, бой и сохранения на сервере.

Направление обновлено 15 сентября 2026. Приватный репозиторий: [igorbilogubov/AshenFrontier](https://github.com/igorbilogubov/AshenFrontier), ветка `main`. Для новой задачи начните с [STATUS.md](STATUS.md) и [AGENTS.md](AGENTS.md); работа в нескольких чатах описана в [WORKFLOW.md](WORKFLOW.md).

**Опубликованная версия:** https://ashen-frontier.91.99.21.123.sslip.io/ — последняя подтверждённая выкладка `20260915-ts-01`. Новая локальная версия ниже ещё не опубликована.

15 сентября опубликован релиз `20260915-ts-01` (`8f9c931`): TypeScript, характеристики, новый HUD и управление удержанием ЛКМ. Серверные герои сохранены; [проверки выкладки](DEPLOYMENT.md).

Откройте один адрес на разных компьютерах и создайте разных героев: они будут в одной локации, увидят друг друга и одних противников. Участвовавшие в бою получают личные награды. Для переноса своего героя: «Вещи → Скопировать ключ героя», затем поле ключа на экране входа другого устройства. Ключ даёт полный доступ к герою; одновременно он может быть открыт только в одной вкладке. Герои разных серверов не переносятся простым копированием ключа.

## Локальный запуск

Нужны Node.js 24 и локальные бинарники PostgreSQL (`pg_ctl`, `initdb`, `pg_dump`; на этом Mac PostgreSQL 14.20). `npm start` без `DATABASE_URL` создаёт отдельную локальную БД на 127.0.0.1:5473 и не импортирует прежний JSON. Для production/изолированных серверов `DATABASE_URL` обязателен. [Команды базы](docs/DATABASE.md).

```sh
git clone https://github.com/igorbilogubov/AshenFrontier.git
cd AshenFrontier
npm ci
PORT=4732 GAME_PREVIEW_ALIAS=0 npm start
```

Открыть http://127.0.0.1:4732/ после запуска нового процесса. Сначала проверьте `/health` и работающий процесс: общий preview 4732 на этом Mac уже работает с PostgreSQL, второй сервер с теми же данными запускать нельзя. Без переменной `PORT` сервер выбирает 4731 и редирект 4740. Mac/iOS/Android-оболочки, старый пиксельный клиент и эксперимент Godot убраны из рабочего проекта.

На этом Mac основная папка — `/Users/igorbelogubov/Projects/AshenFrontier`, ветка `main`. По запросу пользователя агенты выполняют независимые задачи в отдельных ветках/worktree; координатор объединяет результат по [WORKFLOW.md](WORKFLOW.md). Новые локальные сохранения находятся в PostgreSQL (`data/postgres-local/` хранит кластер/закрытые параметры), прежние `heroes*.json` остаются неиспользуемым архивом. Эти данные не скачиваются из GitHub. Запуск и тесты не требуют Blender. `.nvmrc` фиксирует Node 24.

## Что работает

- Воин, лучник и маг; класс выбирается один раз при создании героя. Ближние удары, стрелы и магические снаряды, по два классовых навыка Q/E с серверным уроном, маной и откатами.
- Один общий мир 110 × 90 м, четыре охотничьих спота и 41 моб, включая Седого вожака; атаки с предупреждением, смерть, возрождение и возврат противников к споту.
- Уровни, опыт и ручные характеристики: 5 очков на старте и за каждый новый уровень, черновик распределения, бесплатный сброс у костра. Мана, регенерация и серверная точность атак.
- Личные стопки золота на земле за каждое подходящее убийство; вещь с шансом 10% у обычного моба и 40% у вожака, без гарантии за первый kill. Подбор вручную ЛКМ. Шесть слотов: оружие, доспех, шлем, сапоги, кольцо, амулет.
- Рюкзак на 16 ненадетых предметов, четыре колонки с крупными иконками и подробным сравнением статов. ПКМ/перетаскивание надевает предмет, а в открытом магазине продаёт. Торговец лагеря предлагает 18 базовых вещей — по шесть для класса.
- Задание «5 существ, вожак, возвращение»; награда выдаётся один раз.
- Другие герои, общий чат, переподключение и подтверждённые PostgreSQL-сохранения с ревизиями/журналом операций.
- Доработанный обычный волк: шаг/рысь по расстоянию, переступание при повороте; сравнение прежней и новой модели в бестиарии.

Три отдельных облика Mixamo, по две визуальные коллекции и десять основ вещей на класс, отдельные движения лука/магии. F включает онлайн-автоохоту внутри одного из четырёх спотов; при отключении она прекращается и добычу автоматически не подбирает. Неподобранное пропадает через 180 секунд или при рестарте. Офлайн-AFK, PvP/PK и дополнительные регионы остаются следующими этапами. Рынок и платежи — дальнейшие этапы [дизайна игры](GAME_DESIGN.md). [Правила добычи](docs/LOOT_VENDOR.md), [характеристики](PROGRESSION.md).

## Управление

| Действие | Управление |
| --- | --- |
| Движение | Удерживать ЛКМ и вести курсор; отпустить — остановиться |
| Ходьба / бег | Shift или кнопка на панели |
| Зум без поворота камеры | Колёсико мыши |
| Подобрать личную вещь или золото / подойти к торговцу | ЛКМ по объекту или подписи; сервер подводит героя |
| Удар в сторону курсора | Пробел / удержание ПКМ повторяют удар |
| Два классовых навыка | Q / E |
| Автоохота внутри отмеченного спота | F |
| Зелье | R |
| Меч / топор воина | 1 / 2 |
| Характеристики героя | C |
| Снаряжение и рюкзак | I; ПКМ/перетаскивание для надевания, в магазине — продажи |
| Чат | Enter |

ЛКМ над врагом задаёт только движение; он не атакует автоматически. Без нажатия мыши герой не поворачивается за курсором. WASD и стрелки не перемещают персонажа; миникарта служит только для ориентации. Подход к добыче/торговцу — отдельная проверяемая сервером команда, которую ручное движение отменяет.

## Стек и документы

Выбранное направление — **Three.js + TypeScript**, браузерная основа и desktop на том же клиенте: [подробности и план FPS](TECHNICAL_DIRECTION.md). Текущая реализация — строгий TypeScript, Three.js/WebGL, GLB + AnimationMixer; Node.js HTTP и `ws`. Сборка в `dist/`, `shared/types.ts` задаёт контракты мира/протокола. Тесты и инструменты — JavaScript; сторонний Three.js в vendor не переписывается. Сервер считает движение, попадания, здоровье, добычу и прогресс. Клиент предсказывает движение и плавно показывает полученные состояния.

GitHub Actions проверяет код и тесты в PR и после push в `main`. Автоматического deployment нет: опубликованная игра обновляется отдельно по [DEPLOYMENT.md](DEPLOYMENT.md).

### Сборка TypeScript

`npm run typecheck` проверяет типы без выпуска файлов. `npm run build` компилирует клиент, сервер и общие правила. `npm start` и `npm test` сначала собирают проект. Редактировать нужно `.ts`, не `dist/`; после серверных изменений процесс перезапускается. URL браузера остаются `.js`, HTTP не отдаёт исходники `.ts` и sourcemaps. Docker собирает TS отдельным этапом; runtime устанавливает только production-зависимости.

### Проверка FPS

`npm run stress` поднимает отдельный мир на 4742 с временными героями. Откройте `http://127.0.0.1:4742/?stress=1&session=benchmark` и нажмите «Запустить весь тест» либо выберите один сценарий. `STRESS_PORT=4743 npm run stress` выбирает другой свободный порт. Держите вкладку активной; не меняйте окно/управление во время замера. `npm run stress:report` собирает сохранённые JSON в `artifacts/performance/summary.md`. После тестирования остановите процесс Ctrl+C. Методика и текущие результаты: [PERFORMANCE.md](PERFORMANCE.md).

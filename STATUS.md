## Принятое направление — 15 сентября

Основная версия — браузерная, стек Three.js + TypeScript, интерфейс HTML/CSS; desktop использует тот же веб-клиент. Клиент, сервер и общие правила переведены на строгий TypeScript; новая desktop-оболочка ещё не выполнена. Godot-проба приостановлена и сохранена. Сначала профилирование FPS и устранение измеренных причин; Rust/Wasm рассматривается только для подтверждённых тяжёлых вычислений. Решение, проверенные особенности кода и порядок работ: [TECHNICAL_DIRECTION.md](TECHNICAL_DIRECTION.md).

## Реализовано

Один общий браузерный 3D-мир «Пепельная опушка»: лагерь, четыре волка, два кабана, вожак. Авторитетный сервер 20 Гц управляет движением, боем, личной добычей и сохранениями. Работают три класса с неизменяемым выбором при создании героя, шесть слотов, рюкзак, первая задача, общий чат и перенос ключа героя на другое устройство. Добавлены ручные характеристики и очки за уровни, точность, мана/регенерация, окна персонажа и инвентаря; сохранения версии 3 с миграцией версии 2. Правила: [PROGRESSION.md](PROGRESSION.md). Подробности: [GAME.md](GAME.md).

Старый пиксельный клиент и нативные оболочки убраны. Камера не вращается, колесо меняет зум, Shift переключает шаг/бег. Движение и преследование работают при удержании ЛКМ за текущим курсором и прекращаются при отпускании. Пассивный поворот за мышью, WASD/стрелки и маршрут по миникарте отключены. Воин — Blender/Mixamo, животные — собственные Blender-генераторы. Обычный волк доработан: восемь клипов, включая два разворота, фаза шага по пройденному расстоянию. В бестиарии есть «до / после». Кабан и вожак пока с прежними шестью клипами.

## Проба Godot — локально

По запросу пользователя добавлен отдельный [Godot-клиент](godot-prototype/README.md) с воином, прежними GLB животных, фиксированной камерой, удержанием ЛКМ, боем и сохранениями существующего Node-сервера. Godot Web — 4741, общий для этой пробы backend и Three.js — 4733, отдельные данные `data/godot-prototype/`. Ранее запускалась также локальная macOS-проба; 15 сентября тестовые процессы остановлены для профилирования Three.js. Основной клиент 4732 и production не заменены. Всё остаётся в `codex/character-stats`, без push.

Окружение упрощено; это тест интеграции, не равный FPS-бенчмарк. Полные окна статов/вещей, выбор классов и чат ещё не перенесены. 15 сентября выбран Three.js с переходом на TypeScript и браузер в качестве основы; дальнейшая миграция на Godot приостановлена. Мобильная версия не проверялась.

## Где проверено

- Новый нижний HUD: круглая красная колба HP слева, синяя MP справа, центральные кнопки между ними; цифры и уровень жидкости обновляются по состоянию героя. Проверены узкий/широкий браузер и частичное заполнение маны. Изменение остаётся локальным в `codex/character-stats` на порту 4732.
- Для новой версии со статами и управлением удержанием ЛКМ локально проходят 59 тестов. Последняя опубликованная игровая версия проверялась отдельным набором из 31 теста. Команды: `npm run check`, `npm test`; детали в [QA.md](QA.md).
- Последний проверенный игровой deployment — `20260914-3d-03`: [общий мир](https://ashen-frontier.91.99.21.123.sslip.io/), [бестиарий](https://ashen-frontier.91.99.21.123.sslip.io/game/creature-preview.html).
- В момент этой выкладки сохранены все 15 героев, Caddy, девять других контейнеров и шесть HTTPS-сайтов. Это снимок проверки, не вечное количество игроков. Текущую инфраструктуру перечитать перед следующим deployment.
- Версия со статами и новым управлением подготовлена локально в ветке `codex/character-stats`, preview http://127.0.0.1:4732/. Push ожидает отдельной команды пользователя, production остаётся на указанном выше релизе.
- GitHub содержит также подготовку к параллельной разработке; публикация кода в GitHub не обновляет сервер автоматически.

## Что ещё не сделано

Сохранённые наборы сборок, дополнительные классовые навыки, AFK-загоны, дуэли/PvP/PK, дополнительные регионы/боссы, партии и гильдии, рынок, аккаунты с восстановлением, транзакционное хранилище и платежи. У лучника/мага пока тело и временные клипы воина с отдельным оружием. Полное визуальное переодевание не подключено.

На M1/Chrome проведён воспроизводимый тест 1/4/16 сессий и диагностика рендера. Основной ограничитель — клиентский вывод сцены; стабильные 60 FPS ещё не достигнуты. Устранены 14 дублирующих скелетов внутри каждого клона героя, внешний вид и клипы сохранены. Подробные цифры, условия и ограничения: [PERFORMANCE.md](PERFORMANCE.md). На переходах анимаций ещё возможно скольжение лап. 16 сессий проверены кратко локально, длительная работа и production-нагрузка ещё не проверялись. JSON-сохранения и гостевой ключ — основа текущей альфы, не готовая рыночная экономика.

## Ближайшие независимые задачи

| Направление | Ограниченная первая задача | Зависимости |
| --- | --- | --- |
| Развитие | Испытание ручных сборок и первый AFK-загон | Использовать контракт [PROGRESSION.md](PROGRESSION.md), не создавать вторую систему статов |
| Графика | Полировка моделей отложена: сначала игровая основа | Возвращаться к моделям по следующему запросу |
| Производительность | Воспроизводимый замер CPU/GPU и кадра в той же сцене | Не менять баланс и серверную экономику |
| Мир | План геометрии следующего спота и механики элиты | Общая карта и серверные препятствия должны совпадать |
| Надёжность | Контракт аккаунтов, хранения и идемпотентных выдач | Основа для долгого AFK и рынка |

AFK использует окончательные контракты статов/выдач, PvP — контракт боя и безопасных зон. Эти части не стоит независимо переписывать в нескольких ветках одновременно. Выбирай конкретную задачу из запроса пользователя; таблица не запускает все направления автоматически. Порядок MVP и продуктовые гипотезы: [GAME_DESIGN.md](GAME_DESIGN.md).

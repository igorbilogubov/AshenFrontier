Дополнительные clone/worktree и переключение общей ветки без прямого запроса пользователя не создаются и не выполняются.

Приватный репозиторий: [igorbilogubov/AshenFrontier](https://github.com/igorbilogubov/AshenFrontier). Последние изменения из `codex/character-stats` включены в локальный `main` без переписывания истории. Бывшая дополнительная рабочая папка удалена после переноса данных. Локальные коммиты ещё не означают публикацию в GitHub или обновление production.

## Начало задачи

Прочитай [AGENTS.md](AGENTS.md), [STATUS.md](STATUS.md), [GAME.md](GAME.md), затем документы своего направления. Проверь текущую ветку, `git status --short`, `git worktree list` и последние коммиты. Сохраняй чужие незакоммиченные изменения. Не выполняй автоматические `reset`, `clean`, `checkout` или `pull`, которые могут затронуть текущую работу другого чата.

Нужен Node.js 24 (`.nvmrc`). `npm ci` восстанавливает зависимости из lock-файла; не запускай установку параллельно с чужой сборкой. Blender нужен только для изменения моделей. Исходники Blender/FBX и GLB входят в репозиторий, герои и секреты — нет.

## Общий локальный сервер

Основная проверка игры — http://127.0.0.1:4732/. Перед запуском проверь `/health` и владельца порта:

```sh
lsof -nP -iTCP:4732 -sTCP:LISTEN
curl --fail http://127.0.0.1:4732/health
```

Если сервер уже работает из общей папки, используй его. Иначе из `AshenFrontier`:

```sh
PORT=4732 GAME_PREVIEW_ALIAS=0 npm start
```

Сохранения — `data/heroes.json`. В одном хранилище одновременно работает только один сервер; отдельный порт сам по себе не изолирует данные. Не запускай второй обычный сервер ради проверки другой задачи. Перезапуск после изменения серверных модулей согласуется с активной проверкой другого чата; остановка — штатная, с сохранением героев.

`npm test` создаёт временные серверы/данные. Для FPS используй `npm run stress`: отдельный порт 4742, временное хранилище и методику [PERFORMANCE.md](PERFORMANCE.md). Этому стенду не нужна дополнительная рабочая папка. Не подставляй в него обычный `data/` или production.

## Параллельные чаты

В начале задачи обозначь цель и конкретные файлы. Одновременно можно изменять непересекающиеся модули. Общие файлы (`world.ts`, `public/rules.ts`, `location.ts`, `network.ts`, `scene.ts`, `interface.ts`, конфигурация сборки и lock-файл) изменяет одна задача за раз; зависимая работа ждёт согласованного контракта.

Не отменяй чужие изменения и не коммить их как свои. Перед коммитом повторно проверь diff и индекс; если другой чат уже подготовил файлы, сначала согласуй завершение его коммита. После чужого изменения общего контракта перечитай код и повтори нужные проверки. Общая папка не обеспечивает изоляцию задач автоматически.

Один `.blend`/`.glb` изменяет одна задача. Генератор перезаписывает исходник и экспорт: сначала читай README ассета. В изменение входят согласованные исходники, GLB, отчёт и визуальная проверка. Git не объединяет два бинарных варианта.

## Проверки и локальные коммиты

```sh
npm run check
npm test
git diff --check
git status --short
git add <конкретные-файлы-задачи>
git diff --cached --stat
git commit -m "Describe the completed change"
```

Фиксируй каждое завершённое логическое изменение отдельным локальным коммитом. **Push — только после отдельной команды пользователя.** Коммитить `data/`, `artifacts/`, ключи, `.env`, локальные бэкапы и логи нельзя. Документы обновляются вместе с поведением: STATUS/GAME, QA, дизайн или README ассета. Датированные результаты сохраняют исторический смысл.

GitHub Actions проверяет типы, синтаксис и тесты на Node 24 для PR и push в `main`; автоматической выкладки нет. PR и синхронизация с удалённой веткой выполняются, когда это входит в запрос, с учётом незавершённой работы в общей папке. Force push в `main` не используется. Production — по [DEPLOYMENT.md](DEPLOYMENT.md).

# Параллельная разработка через ветки

Обновлено 15 сентября 2026 по новому запросу пользователя. Основная интеграционная папка — `/Users/igorbelogubov/Projects/AshenFrontier`, ветка `main`. Пользователь теперь прямо разрешил и попросил отдельные ветки и рабочие каталоги для сабагентов; это заменяет прежнее требование всем редактировать одну папку.

## Порядок работы

1. Координатор проверяет `git status --short`, `git worktree list`, актуальные STATUS/GAME и зависимости задач.
2. Каждая независимая задача получает ветку `codex/<task>` и отдельный git worktree в `/Users/igorbelogubov/Projects/.ashen-worktrees/`. В основной папке ветка остаётся `main`. Агент работает и коммитит только в назначенном каталоге; путь задаётся явно в каждой shell-команде.
3. До начала параллельных правок координатор закрепляет владельцев общих файлов/контрактов. Зависимые изменения согласуются сообщением; независимые файлы выполняются параллельно. Бинарный ассет имеет одного владельца.
4. Агент делает локальные коммиты, запускает подходящие проверки и передаёт ветку, изменённые контракты, результаты и ограничения. Агент не выполняет merge/push/deployment и не перезапускает общий сервер.
5. Координатор проверяет diff, последовательно объединяет ветки в `main`, разрешает конфликты, запускает общие `npm run check`, `npm test` и браузерную проверку. Готовые worktree можно убрать после успешного merge и проверки чистоты; история остаётся в Git.

## Выбор модели

Пользователь разрешил выбирать GPT‑5.6 для ограниченных правок кода, тестов и вспомогательных задач, чтобы экономить лимит. Для 3D-моделей, графики, сложной архитектуры/интеграции — GPT‑6 Astra. Координатор выбирает модель по сложности конкретной задачи, а не автоматически запускает всё на самой дорогой модели. Число одновременных агентов ограничено возможностями текущей сессии; остальные задачи ставятся следующей волной.

## Сервер и данные

Общий локальный сервер запускается **только из основной папки**: `PORT=4732 GAME_PREVIEW_ALIAS=0 npm start`. До запуска проверить `/health`, PID и cwd. Не создавать второй процесс с общим `data/` и не останавливать активную пользовательскую проверку. После изменения серверных модулей координатор делает штатный перезапуск с резервной копией при отсутствии игроков.

Тесты агентов используют временные данные и разные свободные порты. `npm test` создаёт свои временные серверы; FPS — изолированный `npm run stress` по PERFORMANCE.md. Данные `data/`, `.env*`, ключи, содержимое heroes*.json, резервные копии и artifacts не коммитить и не выводить. Не копировать обычные сохранения в worktree.

Node 24, `npm ci` в каждом worktree. Blender-генераторы перезаписывают только назначенные ассеты после чтения README. Новые модели проверяются по экспортированным GLB в браузере.

## Проверки и передача

Логические изменения фиксируются локальными коммитами. Документы обновляются вместе с поведением: STATUS/GAME/QA, дизайн, ASSETS/README ассета. Чтобы не создавать конфликты, агенты пишут результаты в отдельный документ своей задачи, а координатор обновляет общие сводки при интеграции. Исторические результаты не переписывать как новые.

Push — только по отдельной команде пользователя. Merge не запускает deployment. Production — только в рамках явного запроса, по DEPLOYMENT.md, с сохранением героев, Caddy и остальных сайтов. Force push в main не выполнять.

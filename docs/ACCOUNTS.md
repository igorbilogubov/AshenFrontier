# Аккаунты и выбор персонажа

Локальная реализация 16 сентября 2026. Код объединён в `main`; текущий production `20260916-consumables-afk-01` ещё использует прежний вход. Настоящий Google OAuth-вход требует выбранного проекта и настроенных credentials, он не подтверждается тестами с искусственными аккаунтами.

## Правила

- Регистрация и вход объединены в кнопку Google. Постоянная идентичность — проверенный Google `sub`; совпадение email не объединяет аккаунты.
- После входа открывается выбор героев. До пяти персонажей на аккаунте, воин/лучник/маг, класс неизменяем. Создание сохраняет героя сразу; вход в мир — отдельная кнопка.
- Одновременно аккаунт управляет только одним героем. Вторая вкладка, другое устройство и другой персонаж того же аккаунта получают `in_use`; действующая игра продолжается.
- Возврат к выбору разрывает игровое соединение, сохраняя вход в аккаунт. При недавнем бое прежний герой остаётся в мире до окончания прежнего таймера отключения; другим героем можно войти после его сохранения и удаления из симуляции. Тот же герой может переподключиться.
- Выход из аккаунта отзывает текущую cookie-сессию и закрывает использующие её игровые соединения. Истечение сессии останавливает также AFK, даже если браузер присылает только WebSocket pong.
- Сохраняются прежние предметы, броски, уровни, характеристики, сундук, зелья и AFK-настройки конкретного героя. Сундук пока личный у героя, не общий между пятью героями.

## API

| Запрос | Результат |
| --- | --- |
| `GET /api/account` | `configured`, `account` или null, только свои `characters`, `maxCharacters:5`; no-store |
| `POST /api/characters` с `{name,classId}` | 201 `{character:{id,name,classId,level}}`; 401 без входа, 400 невалидное имя/класс, 409 `character_limit` |
| `GET /auth/google` | Переход к Google |
| `GET /auth/google/callback` | Проверка Google и создание HttpOnly-сессии |
| `POST /auth/logout` | Отзыв текущей сессии; очистка cookie |
| WebSocket `/ws` | `join {protocol:3,heroId}` → `welcome {protocol:3,id,chat}` → `state` |

POST и WebSocket требуют точный Origin. Секрет cookie не читается JavaScript; heroId — идентификатор, не право доступа. В каждом входе проверяются аккаунт, принадлежность героя и срок сессии. Старый protocol 2 отклоняется; выдача/копирование/вставка ключей героя удалены. Прежние `frontier-token:*` значения удаляются клиентом, в сеть не отправляются.

Лимит пяти защищён блокировкой строки аккаунта внутри транзакции, уникальными слотами 1–5 и DB-триггером. Одновременные HTTP-запросы не создают шестого героя. Общий writer-lock PostgreSQL оставляет одну авторитетную симуляцию мира; резервирование аккаунта выполняется до асинхронных этапов WebSocket-входа.

## Прежние тестовые герои

Миграция schema 5 удаляет `heroes.token_hash`, сохраняя существующие строки и связанные вещи без `account_id`. Они не выдаются первому вошедшему Google-аккаунту и недоступны по прежнему ключу. Автоматического присвоения старых героев нет. Решение о необходимости отдельной привязки старых тестовых героев запрошено у пользователя; обычная локальная и production-базы этой задачей пока не мигрировались. Если перенос понадобится, нужен отдельный административный путь с подтверждённым владельцем.

Откат одного контейнера к старому коду после schema 5 несовместим: старый код ожидает удалённый столбец и прежний контракт. Следует выпускать совместимое исправление. Новые резервные копии и отдельные аудиты production-героев сейчас пропускаются по указанию пользователя; это не разрешение удалять базу.

## Проверки и изоляция

Обычные сетевые тесты создают OAuth-идентичность и cookie непосредственно в своей временной PostgreSQL. В сервере нет тестового маршрута входа. Только уже существующий `GAME_STRESS` с проверенным временным каталогом, loopback-БД и запретом production открывает `/api/stress-session` для наблюдателя и ботов; они тоже входят protocol 3 и отдельными аккаунтами.

Проверки подписанных Google JWT, миграций, сохранений, шестого героя, чужого персонажа, двух окон, logout, истечения AFK и гонок переподключения описаны в [QA](../QA.md). Настройка настоящего Google — [GOOGLE_AUTH_SETUP](GOOGLE_AUTH_SETUP.md); детали таблиц — [ACCOUNTS_STORAGE](ACCOUNTS_STORAGE.md).

# Сохраняемые настройки автоохоты — 15 сентября 2026

Серверный контракт, PostgreSQL-сохранение и панель настроек опубликованы в `20260915-camp-afk-01` (`76a38ec`). Неподвижная автоохота в любой допустимой точке, исправление нажатия шестерёнки и расход через назначаемые Q/W опубликованы в `20260916-consumables-afk-01` (runtime `7b5a7b7`). [Текущее поведение](AFK_STATIONARY_SERVER.md), [выкладка](../DEPLOYMENT.md), [проверки](../QA.md).

В подготовленном коде AFK применяет пороги HP/MP только через Q/W-назначения: ищет слот с зельем нужного вида и доступной бутылкой, поэтому неназначенный запас не расходует. Оба слота могут быть переставлены или содержать один вид; откаты остаются независимыми по ресурсу. Изменение проверено временными БД, сетевыми тестами и в браузере. [Правило расходников](CONSUMABLE_INVENTORY_SERVER.md).

`afkPreferences` хранится у героя и возвращается только в `state.self`. Режим `self.afk` остаётся временным: сохранение настроек, переподключение и рестарт не включают автоохоту автоматически. Пока AFK включена, `self.afkXpMinute` — сумма опыта за последние 60 секунд; журнал грантов живёт только в памяти процесса и в PostgreSQL не пишется. Команда `{type:'afkPreferences',preferences}` принимает полный объект; приватное событие `preferencesSaved {ok,message?}` сообщает результат. Сервер отклоняет неполные поля, неверные типы, дубли редкостей/навыков, навыки чужого класса и значения вне границ. Обновление настроек само по себе не останавливает активную автоохоту.

```ts
interface AfkPreferences {
  pickupGold:boolean;
  pickupRarities:number[]; // любая выборка из 0, 1, 2, 3, 4
  hpPotion:{enabled:boolean;belowPercent:number};
  manaPotion:{enabled:boolean;belowPercent:number};
  attackSkill:SkillId|null; // ровно один установленный атакующий/канальный/контрольный навык или пусто
  buffSkills:SkillId[]; // установленные защитные и поддерживающие навыки, без порядка
  basicAttackFallback:boolean;
  radiusPercent:number;
}
```

Новый герой и прежний герой без этого поля получают: сбор золота и редкостей 0/1/2/3/4, HP-зелье ниже 35%, MP-зелье ниже 25%, первый атакующий навык класса без бафов, обычную атаку при недоступности навыков и 100% дальности выбранной атаки. Сохранённый прежний `skillOrder` при загрузке превращается в первый атакующий навык списка и включённые бафы. Панель позволяет задать порог зелья 5–95%; серверный контракт принимает целый процент 1–99; `enabled:false` выключает его расход. Радиус выбора целей — 25–100% максимальной дальности выбранной атаки и разрешённой обычной атаки. Каждая атака дополнительно проверяет собственную дальность, тело цели и препятствия. Процент радиуса больше не задаёт перемещение: герой остаётся в точке включения. В безопасной зоне режим ждёт без атак.

AFK подбирает только личное золото при `pickupGold:true` и только личные вещи с выбранной редкостью при свободном рюкзаке. Подбор использует отдельную серверную дистанцию 4 м без перемещения; за дальней добычей герой не ходит. Ручной подбор остаётся ограничен 1,4 м и при клике может подвести героя. Остальные стопки остаются на земле до обычного срока жизни; AFK продолжает бой при полном рюкзаке, пустой волне или отключённых фильтрах.

Сервер сначала применяет включённые бафы сразу по окончании отката, если эффект или зона ещё не активны, без порогов HP/MP. Затем использует выбранный атакующий навык. Если он недоступен по мане, откату или дистанции, обычная атака разрешена только при `basicAttackFallback:true`. Пустой `attackSkill` и пустые `buffSkills` допустимы. Перемещения в автоохоте не используются. Урон, попадания, откаты, расход маны/зелий и награды используют существующие серверные методы боя. Ручное движение, удар и навык по-прежнему останавливают AFK; нейтральные сетевые пакеты и сохранение панели не останавливают.

Миграция PostgreSQL 3 добавила `heroes.afk_preferences jsonb` транзакционно. Schema 4 расходников сохраняет это поле без изменения; существующие ID/броски предметов, сундук, золото и настройки AFK не переписываются. Старые герои без поля читаются с настройками по умолчанию для их сохранённого класса. Экономический снимок включает настройки, чтобы сервер подтвердил изменение в базе до следующего сетевого состояния. `/health` проверяет актуальную схему и сообщает фактическую версию. Проверки выполняются на временных PostgreSQL и свободном сетевом порту.

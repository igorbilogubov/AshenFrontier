# Зелья в рюкзаке и назначение Q/W

Обновление 16 сентября: четыре размера HP/MP, до 999 в стопке и покупка по 1/50; прежние лимиты 50 ниже описывают историю первой версии. [Актуальные правила](POTION_TIERS.md).

Реализация 15 сентября 2026 опубликована в `20260916-consumables-afk-01` (runtime `7b5a7b7`, PostgreSQL schema 4). Доказательства среды и публичного контракта находятся в [журнале выкладки](../DEPLOYMENT.md).

Зелья теперь хранятся в `consumableInventory`: каждый стек имеет стабильный `id`, `definitionId` и положительное `quantity`. Каталог `public/game/consumables.ts` содержит `hp-basic` (+45 HP, 6 золота) и `mana-basic` (+40 MP, 8 золота); определения позволяют добавлять варианты с иным восстановлением без изменения формата инвентаря. Сохраняются прежние пределы 50 бутылок каждого ресурса и независимые четырёхсекундные задержки HP/MP.

Один непустой стек занимает ячейку общего рюкзака. Стартовая вместимость — 16, докупка до 40 через `bagCapacity`. `backpackUsage` считает ненадетое снаряжение вне сундука плюс стеки. Подбор, покупка снаряжения, получение прежних ожидающих наград, снятие вещи и извлечение из сундука используют эту вместимость. Покупка бутылки может пополнить имеющийся стек даже в полном рюкзаке; новый стек требует свободную ячейку. Сундук по-прежнему хранит только снаряжение.

`quickSlots: {q, w}` содержит идентификаторы определений или `null`. Команда `assignConsumable {slot, definitionId}` назначает только принадлежащий герою тип либо очищает слот; назначение ничего не расходует. Команда `useConsumable {slot}` использует назначенный тип. В любой слот можно назначить HP или MP, оба слота могут ссылаться на один тип без копирования бутылок. Исчерпанный стек удаляется, но его назначение сохраняется: повторная покупка того же типа снова делает слот доступным. Полный ресурс, смерть, пустой слот, отсутствие бутылок и задержка не расходуют запас.

AFK соблюдает HP/MP-пороги и выбирает только назначенный тип нужного ресурса. Неназначенный запас не используется. Прежняя команда `potion {kind}` сохраняет смысл явно указанного ресурса даже при перестановке Q/W. Поля `potions`/`manaPotions` остаются производными суммами для совместимости; правила покупок и расхода используют стеки. Смена назначения и любое изменение стеков включены в экономический барьер: PostgreSQL подтверждает изменение до сетевого состояния.

## Миграция PostgreSQL 3 → 4

Миграция добавляет `consumable_stacks`, два столбца назначения и `consumable_overflow`; копирует точные положительные старые счётчики в стеки. Герои, старые колонки, ревизии, золото, ресурсы, характеристики, экипировка, броски вещей и сундук остаются неизменными. `SAVE_VERSION` героя остаётся 3: это предотвращает повторную миграцию распределённых характеристик и заполнение маны.

Если старые вещи и полученные из счётчиков стеки временно занимают 17–18 ячеек, существующий герой сохраняет всё. `consumableOverflow` разрешает только эти исходные 1–2 дополнительные ячейки и сокращается при освобождении места. Хранилище отклоняет увеличение разрешения, новые игровые поступления всё равно требуют обычную вместимость 16. Ничего не удаляется для приведения к новому пределу.

Перед изменением схемы проверяется блокировка работающего мира. Новый writer получает её до миграции; открытие в режиме reader также не может мигрировать базу, пока её удерживает старый writer. Уже обновлённая схема доступна reader рядом с действующим writer. Это исключает копирование счётчиков, пока старый сервер ещё покупает или расходует бутылки. Для следующих выкладок применять актуальные ограничения AGENTS.md и процедуру DEPLOYMENT.md; сам запуск кода не обновляет production автоматически.

## Проверки

Реальные временные PostgreSQL и WebSocket покрывают точную миграцию старого полного рюкзака, неизменность прежних колонок/вещей/ревизии, сохранение стеков и назначений, повтор операции, перезапуск, убывание разрешённого переполнения и отказ миграции рядом с прежним writer. Сетевой тест сравнивает подтверждённый снимок с уже записанной базой после назначения, расхода и покупки. Правила мира проверяют все пути увеличения рюкзака, два слота одного типа, независимые задержки, повтор расхода, освобождение пустого стека, повторную покупку и AFK после перестановки Q/W.

Итоговая проверка release-кода с актуальными AFK и UI: `npm run check` пройден; `npm test` — 212/212 без пропусков в Docker, CI run `35061101790` успешен. Проверка stress health ожидает до 5 секунд только штатную фазу `writer:true,pending:true`, поскольку `/health` преднамеренно возвращает 503 на время подтверждения записи; потеря writer не игнорируется. Production обновлён отдельно по процедуре выкладки.

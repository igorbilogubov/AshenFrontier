# Сетевые тесты PostgreSQL

15 сентября 2026. Сетевые тесты теперь проверяют настоящий PostgreSQL и отдельную новую базу `ashen_test_<случайный идентификатор>` для каждого случая. Административный адрес даёт `GAME_TEST_DATABASE_URL`; сами тесты не показывают адрес и не используют обычные сохранения героя. Вспомогательный модуль `test/helpers/postgres.mjs` удаляет только созданную им базу после остановки тестового сервера. Установка и запуск тестового PostgreSQL выполняются общим test runner.

В прежних сценариях HTTP, движения, групповой награды босса, распределения характеристик, экипировки, навыков и онлайн-автоохоты поведение WebSocket остаётся предметом проверки. Вместо подготовки `heroes.json` тесты явно сохраняют героев в тестовую базу, а после остановки читают её состояние через `openHeroStore`. Сценарии миграции старых JSON-героев удалены из сетевого слоя: автоматический импорт JSON не входит в этот этап. Отдельный новый тест проверяет, что даже испорченный `heroes.json` остаётся нетронутым и не мешает запуску с новой базой, а без `DATABASE_URL` сервер вообще не запускается. Второй экземпляр игрового сервера не может занять ту же базу, первый остаётся доступным, штатный рестарт освобождает блокировку. Проверка `safeHero` старых версий в чистых тестах остаётся.

После объединения веток координатор запускает `npm run check` и `npm test` с изолированным PostgreSQL, затем проверяет путь рестарта и `/health` на временном сервере. Push и production не входят в эту задачу.

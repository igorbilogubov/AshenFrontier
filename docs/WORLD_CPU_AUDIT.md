# Серверный тик: 711 мобов, 16 героев

Локальная проверка 16 сентября 2026 на Apple M1 / Node 24.19.0. Это измерение серверной симуляции в памяти, без PostgreSQL, сети, рендера или обычных сохранений. Оно не подтверждает клиентские 60 FPS или пропускную способность production.

## Найденные причины и изменение

Профиль 16 одновременно работающих AFK показал 40.7% выборок в `dungeonAt`, 15.1% в `lateRegionAt`, 6.1% в `lateSafe` и ещё около 11% в их callback-функциях. Характеристики героя занимали менее 1%; кешировать их не потребовалось.

`world.ts` запоминает результат определения карты и безопасной зоны в `WeakMap` до изменения X **или** Z объекта. Проверка координат работает также между тиками: переходы, возрождения и переносы в тестах сразу получают новый результат. Слабые ключи не удерживают удалённые объекты. Геометрия карт статична; характеристики, вещи, таланты, бафы, здоровье и состояние боя не кешируются.

Второй профиль выявил лишние проверки видимости при взрыве снаряда: `clearPath` вызывался для далёких мобов карты до проверки радиуса. Теперь радиус проверяется первым. Аналогично, поиск цели мобом сначала отбрасывает слишком далёких игроков. Сам набор подходящих целей, порядок сортировки и правила урона сохранены.

## Воспроизведение

```sh
npm run build
node scripts/benchmark-world-tick.mjs --players=16
node scripts/benchmark-world-tick.mjs --players=1
node scripts/benchmark-world-tick.mjs --players=16 --afk=false
```

Скрипт создаёт только временные объекты JavaScript: 16 магов со стартовой атакой, размещённых на всех 15 картах (в лесу двое). Уровень 100; HP/MP восстанавливаются перед каждым тиком, чтобы гибель и запас зелий не прекращали нагрузку. Это насыщенный тест AI/снарядов, а не проверка боевого баланса. Мир содержит все 711 спавнов.

Шаг 50 мс, 1200 тиков: 200 для прогрева, 1000 для измерения. Раз в 20 тиков отдельно формируются и JSON-сериализуются снимки всех игроков. Измеряются wall-clock и `process.cpuUsage`; снапшоты не входят во время тика. **Сумма p95 этих двух распределений не является p95 полного серверного цикла**; цикл с отправкой сети и записью в БД не измеряется. С `--compare` предыдущий `world.ts` берётся из указанного локального коммита и запускается с **текущими общими данными**, сравнивая именно алгоритм симуляции. Варианты чередуются по одному тику с одинаковым seed. Проверяется хеш конечных позиций, HP, состояний мобов, атак, снарядов и добычи без случайных UUID/абсолютных timestamp.

### Повтор исторического A/B

Таблица A/B ниже измеряет модуль мира из локального коммита `337159a` против `5670bd3`, с одинаковыми общими данными. Для точного повтора команда `node scripts/benchmark-world-tick.mjs --players=16 --compare=5670bd3` выполняется в отдельной рабочей копии `337159a`. Последующий `main` также ограничивает начальную паузу патруля: `.8 + (id % 12) × .17` вместо неограниченного роста `.8 + id × .17`. Это намеренно меняет движение новых мобов, поэтому проверка равенства хешей с прежним поведением должна его обнаруживать. Текущую производительность измеряет обычный запуск без `--compare`.

## Регрессии

`test/world-spatial-queries.test.mjs` переносит одни и те же объекты через все карты без промежуточного тика и проверяет состав снимков. Отдельно проверяется немедленное включение/отключение защиты при изменении только X, затем только Z героя и цели.

При аудите также обнаружены и исправлены координатором два правила подземелий: root/slow теперь влияют на движение босса; через 180 секунд после его смерти оставшихся героев переносят к безопасному входу, останавливают AFK и обновляют стражей. Это не позволяет одному оставленному персонажу навсегда удерживать очищенное общее подземелье. Частичный поход с живым боссом сбрасывается после 600 секунд отсутствия живых подключённых героев за пределами входа.

## Результат A/B

[Полный числовой снимок](world-tick-performance-2026-09-16.json), одинаковые 1200 тиков, 16 AFK-магов. Предыдущая версия — `5670bd3`, общие данные в обеих ветках одинаковы.

| Измерение, мс | До | После |
|---|---:|---:|

Обе версии завершили ровно 170 убийств; проверяемый хеш конечного состояния боя полностью совпал (`2772e637b6ed62fa3e89f371d419be4b667df0e20acc6c342ae1a032453308b1`). Средний CPU тика уменьшился примерно в шесть раз. Измеренный p95 тика ниже бюджета 50 мс; один максимальный тик превысил его. Другие приложения на Mac не закрывались, возможны конкуренция за CPU, сборка мусора и системные задержки. Эти числа не являются гарантией отсутствия сетевых задержек или просадок кадров.

Один AFK-маг: тик mean 2.30 мс / p95 3.76 мс, снимок p95 2.19 мс; в это время шли целевые регрессии, поэтому это не замер на свободной машине. `npm run check` прошёл. Целевой набор на момент передачи: 76/77; единственная оставшаяся проверка — требование пяти прогулок у `hellhound#528` за 120 секунд (получено четыре). Ни коротких Walk/Idle-переключений, ни ошибки защиты или боя эта проверка не выявила; координатор отдельно сверяет базовую версию и критерий патруля. Полный набор с PostgreSQL запускает координатор после интеграции.

## Финальный текущий runtime после ограничения патрульных пауз

[Числовой результат](world-tick-final-2026-09-16.json): обычный одиночный запуск после полного тестового набора, 16 AFK / 711 спавнов / 1200 тиков с 200 прогрева. Среднее время тика 6,40 мс, p95 8,31 мс, p99 9,40 мс, максимум 10,62 мс; средний CPU 6,89 мс. Отдельная подготовка и сериализация всех 16 снимков: среднее 4,42 мс, p95 5,64 мс. 170 убийств.

Это новая контрольная точка текущего runtime. Разницу с 23,03 мс из A/B нельзя приписывать исправлению патруля: варианты больше не чередовались в одном процессе, фоновые тесты завершились, часть браузерных сцен закрыта. Параллельная нагрузка Mac и сборка мусора отличаются. Заявление об ускорении алгоритма опирается на сопоставимый A/B выше, а не на сравнение этих двух отдельных запусков.

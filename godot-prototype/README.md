# Godot: проба Пепельной опушки

14 сентября 2026. Отдельный клиент на Godot 4.7.2 / GDScript. Это проверка переноса сцены и управления, а не решение о полной миграции. Основной Three.js-клиент и серверные правила сохранены.

**Статус с 15 сентября: развитие приостановлено.** Пользователь выбрал Three.js + TypeScript, браузерную основу и desktop на том же клиенте. Эта проба сохранена для справки; команды ниже описывают воспроизведение проведённого эксперимента. [Текущее направление](../TECHNICAL_DIRECTION.md).

## Быстрый запуск

Из корня этой рабочей копии, после `npm ci`:

```sh
npm run godot:import
npm run godot:server
```

В другом терминале:

```sh
npm run godot:run
```

Для редактора: `npm run godot:editor` или открыть `godot-prototype/project.godot`. Сцена строится при запуске `main.tscn`; до запуска редактор показывает корневой узел. GLB можно открывать отдельно для просмотра импорта и клипов. `GODOT_BIN` переопределяет путь к Godot; на macOS по умолчанию используется `/Applications/Godot.app/Contents/MacOS/Godot`, на остальных системах — `godot` из PATH.

## Браузер и приложение

Нужны официальные Export Templates той же версии, что установленный Godot. Через редактор: Editor → Manage Export Templates. На этой машине установлены соответствующие Web и macOS templates 4.7.2.stable.

```sh
npm run godot:export
npm run godot:export:macos
```

- Godot Web: http://127.0.0.1:4741/ при работающем `godot:server`.
- Three.js в том же тестовом мире: http://127.0.0.1:4733/.
- Собранное локальное приложение: `artifacts/godot-macos/Ashen Frontier Godot.app`.
- Web-файлы: `artifacts/godot-web/`; это HTTP-приложение, открытие HTML через `file://` не подходит.

macOS-сборка предназначена для локальной проверки, без подписи и notarization для распространения. Windows/Linux, Android/iOS и мобильные браузеры в этой пробе не проверялись. Нативная macOS-проба согласована отдельно; мобильные сборки этим не разрешены.

## Управление

- Удерживать ЛКМ на земле — двигаться за текущим курсором; на мобе — подойти и атаковать. Отпустить — остановиться.
- Простое наведение не поворачивает героя. WASD и стрелки не двигают.
- Колесо — плавный зум. Камера следует за героем с неизменным углом.
- Shift — шаг/бег; 1/2 — меч/топор; Q — раскол; R — зелье; пробел/ПКМ — удар.
- Перетаскивание на нижнюю панель, отпускание и потеря фокуса прекращают движение.
- Кнопка возврата к костру использует обычные серверные ограничения: во время боя возврат запрещён.
- F3 — не содержащий ключ героя диагностический отчёт в журнале и `user://diagnostics.json`.

## Сервер и сохранения

`godot:server` запускает существующий `server.mjs` на **4733**, HTTP-просмотр Godot на **4741**, WebSocket-прокси `/ws` и отдельные сохранения в `data/godot-prototype/`. Оба сокета слушают только loopback. Существующие серверы 4731/4732, их герои, main-worktree и production не меняются. Порты можно задать `GODOT_SERVER_PORT` и `GODOT_WEB_PORT`; при изменении backend-порта нативному клиенту передать `npm run godot:run -- -- --server=ws://127.0.0.1:ПОРТ/ws`.

Клиент отправляет только протокол 2: вход, направление, атаку, переключение бега/оружия, зелье и возврат. Node определяет координаты, столкновения, попадания, здоровье, опыт, золото, вещи и сохранения. Godot интерполирует снимки; предсказание/повтор неподтверждённого ввода из Three.js пока не перенесены. Поэтому этот тест на localhost не доказывает качество движения при сетевой задержке.

При первом запуске автоматически создаётся воин «Страж Godot». Его закрытый ключ хранится в `user://session.cfg`, отдельно для адреса сервера. На macOS это `~/Library/Application Support/AshenFrontier-Godot-Prototype/`, в Web — локальное хранилище Godot внутри браузера. Нативная и браузерная проба создают разных героев, но видят общий мир. Одновременный запуск двух нативных копий с одним ключом будет отклонён существующей серверной защитой. Ключи и серверные файлы героев не выводить и не коммитить.

## Что перенесено

- Исходные GLB воина, волка, кабана и вожака, их скелеты и клипы; исходная текстура земли.
- Все семь мобов, общий бой/телеграфы, здоровье, мана, опыт, золото, смерть/возрождение и серверные награды.
- AnimationTree с ручным выбором времени клипов и смешиванием поз. Шаг связан с расстоянием, поворот волка — с углом, контакт атаки — с серверным таймером.
- Нижние колбы HP/MP, основные кнопки, прогресс первого задания и показатели соединения.
- Совместное отображение игроков и восстановление героя после разрыва и повторного запуска клиента.

## Граница пробы

Создание лучника/мага, их внешность/оружие, интерфейсы статов и инвентаря, чат, миникарта, управление ключом героя и все остальные экраны пока не перенесены. Прототип создаёт воина и отображает других героев с телом/оружием воина; вход лучником/магом через Three.js не делает Godot полноценным клиентом этих классов. Их серверные правила продолжают работать.

Лагерь, лес и руины собраны упрощённо из Godot-мешей. Использованы прежние позиции деревьев и препятствий, но детали окружения, свет, шейдеры, качество теней, сглаживание и обработка анимаций отличаются от Three.js. Это **не равная сцена для сравнительного FPS-теста**. Полировка моделей не возобновлялась, исходные Blender/FBX/GLB не изменялись.

`godot:sync` копирует пять канонических ассетов из `public/game/` и формирует `generated/world.json` из общей карты. Manifest содержит исходные пути и SHA-256. Папки `assets/`, `generated/`, `.godot/` и сборки игнорируются Git; после clone сначала выполнить импорт. После изменения общей карты или моделей повторить `godot:import` и экспорт. Источники и условия использования остаются прежними: [ASSETS.md](../ASSETS.md).

## Проверки и следующий выбор

```sh
npm run check
npm test
npm run godot:test
```

Godot-тест требует выполненного импорта. Он сам запускает временный Node-сервер на свободном порту и в отдельном каталоге, проверяет настоящую WebSocket-сессию, импорт/изменение скелетной позы, управление, фиксированную камеру, зум, бой с наградами и восстановление из записанного ключа. Временные данные удаляются после теста. Он работает headless и **не измеряет GPU или визуальную плавность**. Отдельная проверка Web и macOS описана в [QA.md](../QA.md).

Если пользователь вернётся к сравнению движков, потребуются: игра вручную на обеих версиях, одинаковое окружение и разрешение, замер без одновременной нагрузки других клиентов, сетевой тест с задержкой и потерями, затем одна законченная функция — например экран статов. Перенос игры на Godot приостановлен; другой серверный стек и мобильный релиз не согласованы.
